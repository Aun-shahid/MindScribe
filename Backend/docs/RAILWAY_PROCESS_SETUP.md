# Railway Process Setup (Single Web Process + In-App Scheduler)

The reminder system now uses APScheduler inside the web process (Daphne + Django/Channels). No Celery worker/beat services are required for in-app reminders.

## What changed

`Backend/start.sh` runs one process:
- `PROCESS_TYPE=web` → collectstatic, migrate, then Daphne

The `patients` app starts an APScheduler background job on app startup and checks due reminders every configured interval.

## Required Railway services

Create **1 web service** from this repo/image:

1. **Web service**
   - `PROCESS_TYPE=web`
   - Healthcheck path: `/api/authenticator/health/`

## Environment variables

Required/important:
- `IN_APP_REMINDER_SCHEDULER_INTERVAL_SECONDS` (recommended `30`, valid `10-60`)
- `DAILY_REMINDER_WINDOW_MINUTES`
- `SESSION_REMINDER_WINDOW_MINUTES`

Optional:
- `DISABLE_IN_APP_REMINDER_SCHEDULER=true` to disable background reminder checks

## Why this fixes the issue

In-app reminders are generated by a lightweight scheduler running in the same process as the API and WebSocket server, so reminder creation and live delivery do not depend on separate Celery infrastructure.
